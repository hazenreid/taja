# taja

자판을 처음 배우는 사람을 위한 터미널 타자 연습기입니다 (Rust).

> 이 프로젝트는 Anthropic의 AI 코딩 도구 [Claude Code](https://claude.com/claude-code)를 이용해 만들었습니다.

자주 쓰는 키 몇 개로 시작해서, 열린 키가 **모두** 목표 속도와 정확도를 넘으면 다음 키가 하나씩 열립니다.
연습 문장은 열린 키로만 만들어지고, 모든 단어에 가장 약한 키(집중 키)가 들어갑니다.

## 실행

```sh
cargo run --release                     # 기본 레이아웃 (저장소의 layouts/mine.txt)
cargo run --release -- --layout qwerty  # QWERTY
cargo run --release -- --layout mine    # 레이아웃 폴더의 mine.txt
cargo run --release -- --lang ko        # 한글 (두벌식)
cargo run --release -- --reset          # 진도를 지우고 처음부터 (한글은 --lang ko --reset)
cargo run --release -- --help           # 옵션 보기
```

`cargo run` 뒤에 옵션을 줄 때는 `--` 다음에 적어야 합니다 (`--` 앞은 cargo 옵션).

| 키 | 동작 |
|---|---|
| 글자 | 입력 (틀리면 맞는 키를 칠 때까지 커서가 멈춤) |
| `Tab` | 새 줄 |
| `Esc` / `Ctrl+C` | 저장하고 종료 |

화면 글자, 알림, 오류 메시지, `--help`는 영어로 표시됩니다.

옵션:

- `--lang en|ko`: 연습할 언어 (기본 en)
- `--target-wpm 30`: 키별 목표 속도 (기본 30, 한글은 ×5 해서 150 KPM으로 표시)
- `--target-acc 90`: 키별 목표 정확도 % (기본 90)
- `--reset`: 이 레이아웃의 진도를 지우고 처음부터
- `--paths`: 레이아웃 폴더와 진도 폴더 위치 보기
- `--corpus <경로>`: 영어 언락 순서에 쓸 `corpus.bin` (기본: 저장소의 `assets/corpus.bin`)

## 레이아웃 파일

10×3 글자만 적으면 됩니다. 공백은 무시하고, **영어 글자(a~z)가 아닌 칸은 모두 빈 칸**(키 없음)입니다.
빈 칸은 `.`, `;`, `-` 등 아무 기호로 적으면 됩니다. 내장 QWERTY의 `; , . /` 자리도 빈 칸입니다.

```
qwertyuiop
asdfghjkl;
zxcvbnm,./
```

`taja --paths`로 나오는 레이아웃 폴더(Linux: `~/.config/taja/layouts/`)에 `mine.txt`로 저장하고
`--layout mine`으로 실행합니다. 파일 경로를 바로 줘도 됩니다 (`--layout ./mine.txt`).

**기본 레이아웃: 저장소의 `layouts/mine.txt`** (`--layout`을 안 주면 이 파일을 씀. 빌드할 때 저장소 경로가 들어감)

```
buof.zmlgv
rien.jat.d
wxys.qhkcp
```

이 배열의 계산 결과 (assets/corpus.bin 기준): 시작 키 `e t s h` (4개) → `a r i n o d c l f m u g p w b y v k j x z q`
(영어 상위 트라이그램 중 `ion`, `for`, `res`가 이 배열에서는 롤.
원래 배열의 `^`, `@`, 스페이스 자리는 글자가 아니라서 `.`(빈 칸)으로 적음)
레이아웃은 OS나 키보드 펌웨어에 설치된 상태여야 합니다. 프로그램은 들어온 글자를 그대로 비교합니다.

나머지는 모두 위치로 자동 계산합니다:

- **손가락**: 열 번호로 정함 (0 왼손 새끼 … 3·4 왼손 검지 | 5·6 오른손 검지 … 9 오른손 새끼)
- **시작 키 (4~8개 자동, 빈도 기준)**: 레이아웃의 **모든 글자 키** 중에서, 그 키들(과 공백)로 칠 수 있는
  트라이그램 빈도가 가장 높은 조합을 고름. 자리나 줄은 따지지 않음. 4개부터 늘려 가며, 진짜 단어가 10개 이상
  나오는 조합이 있는 가장 적은 개수에서 멈춤. 조합이 너무 많아서 빔 탐색(단계마다 상위 300개만 남김)으로 찾음
  - 영어(corpus.bin): `e t s h` (4개, `the she these test`를 바로 칠 수 있음)
  - 한글: `ㅏ ㅇ ㄷ ㅎ` (`layouts/mine.txt`) / `ㅏ ㄷ ㄴ ㅎ` (QWERTY). 기본형 끝의 `-다`, `-하다`를 칠 수 있음
  - 자리를 안 따지므로 레이아웃이 달라도 시작 키는 거의 같고, 차이는 그다음 언락 순서에서 남
- **언락 순서 (트라이그램, 빈도만)**: 남은 키마다 "이 키를 열면 이미 열린 키(와 공백)와 함께 새로 칠 수 있게 되는
  트라이그램(세 글자 연속)의 빈도 합"에 글자 빈도를 조금 더한 값이 큰 키부터 엶. **자리 비용은 따지지 않음**
  (빈도로 최적화한 레이아웃이면 흔한 글자가 이미 편한 자리에 있음). 점수가 같을 때만 쉬운 자리가 먼저
  - **롤**(세 글자가 같은 손, 서로 다른 손가락, 한 방향으로 이어짐)인 트라이그램은 1.5배로 쳐줌.
    롤링 레이아웃이면 자주 쓰는 롤 동작이 일찍 열림
  - 영어: `corpus.bin`의 트라이그램 빈도. 파일이 없으면 내장 단어 목록으로 센 값으로 대신함
  - 한글: 내장 단어 목록의 빈도로 두벌식 키 트라이그램을 셈
  - 공백이 든 트라이그램(` th`, `he `)은 공백을 뺀 글자로 셈. 그래서 단어 첫 글자·끝 글자로 많이 쓰이는 키
    (`s`, `d`, `f`(of), `w`, `y`)가 조금 일찍 열림
  - 언락 순서는 진도를 처음 만들 때 계산함. `corpus.bin`을 바꾼 뒤에는 `--reset`으로 새로 시작해야 반영됨
  - 결과 예 (단어는 내장 SCOWL, 순서는 저장소의 `assets/corpus.bin` 기준):
    - QWERTY: `etsh` → `a r i n o d c l m u f g p w b y v k j x z q`
    - `layouts/mine.txt`: `etsh` → `a r i n o d c l f m u g p w b y v k j x z q`
    - 자리를 안 따지므로 레이아웃이 순서에 주는 영향은 롤 가산뿐이라 차이가 작음

### corpus.bin 위치

저장소의 **`assets/corpus.bin`**에 두면 됩니다. 빌드할 때 저장소 경로를 기억하므로 어느 폴더에서 실행해도 찾고,
실행할 때마다 읽으므로 파일을 바꿔도 다시 빌드할 필요가 없습니다 (단, 언락 순서는 `--reset` 해야 새로 계산됨).
다른 파일은 `--corpus <경로>`로 지정합니다.

### corpus.bin 형식

`CorpusStats { letters, bigrams, trigrams }`를 bincode 1 기본 설정(리틀엔디언, 고정 길이 정수)으로 직렬화한 파일.
머리말 뒤에 맵 세 개가 차례로 들어 있습니다. 글자는 UTF-8, 횟수는 u64입니다.

```
"P2ANUT-CORPUS\0" + u32 버전(1) + u32         ← 머리말 (마지막 u32는 안 씀)
[u64 개수] + (char, u64) × 개수               ← letters
[u64 개수] + (char, char, u64) × 개수         ← bigrams (지금은 안 씀)
[u64 개수] + (char, char, char, u64) × 개수   ← trigrams
```

머리말이 없는 예전 형식(맵 세 개만)도 읽습니다. 버전이 1이 아니면 오류를 냅니다.
영어 글자는 소문자로 바꾸고, 영어 글자와 공백이 아닌 글자가 든 항목은 버립니다.
지금 파일: 글자 27(공백 포함), 바이그램 702, 트라이그램 18,237개 (그중 공백이 든 것이 빈도의 45%).

진도는 레이아웃마다 따로 저장됩니다 (Linux: `~/.local/share/taja/profiles/<이름>.json`).
레이아웃 파일 내용이 바뀌면 진도를 새로 시작합니다.

## 언락 기준

- 키마다 최근 30번의 입력으로 평가
- **속도**: 바로 앞 키를 친 뒤 이 키를 칠 때까지 걸린 시간의 평균 (2초 넘게 쉰 입력은 제외)
  - **한 번에 맞게 친 입력만** 씀. 틀렸다 고친 키는 정정하는 시간이 들어가서 뺌 (틀린 것은 정확도에서 셈)
  - **단어 첫 키**(공백 다음)에는 다음 단어를 읽는 시간이 더 들어가므로 보정해서 셈
    - 평소 배율: 열린 키들의 최근 기록에서 "단어 첫 키 시간 ÷ 단어 안 시간"(중간값끼리, 예: 2배)
    - 단어 첫 키 시간을 이 배율로 나눠서 셈. 다음 단어를 읽는 시간은 빠지고,
      그 키를 찾느라 평소보다 더 걸린 만큼은 남음
    - 평소 단어 첫 키 시간의 2배보다 오래 걸렸으면 쉬었다 친 것으로 보고 뺌
  - 그래서 키별 속도는 줄 전체 속도(위쪽 `last line`, 띄어쓰기와 단어 첫 키 포함)보다 빠르게 나옴
- **정확도**: 한 번에 맞게 친 비율
- 열린 키가 모두 20번 이상 입력되고, 목표 속도와 목표 정확도를 넘으면 다음 키가 열림
- 화면: 막대가 꽉 차면 그 키는 통과(초록). 목표에 못 미치는 속도·정확도 숫자는 빨간색
  - 키가 많아서 진행 칸에 다 안 들어가면, 아직 통과 못 한 키를 먼저 보여 주고 통과한 키는
    마지막 한 줄로 줄임 (예: `✓ 24 passed: ㅏ ㄷ ㄴ ㅎ …`)
  - **모든 키를 열고 모든 키가 통과하면 화면 키보드를 숨김** (보지 않고 치도록). 줄을 시작할 때 정하므로
    줄 중간에는 바뀌지 않고, 어떤 키가 다시 목표 아래로 내려가면 다음 줄부터 다시 보임

## 집중 키

연습 줄의 모든 단어에 들어가는 키입니다. 열린 키 중에서 이 순서로 고릅니다.

1. 아직 20번을 못 친 키 (새로 열린 키)
2. **정확도가 목표 미달인 키** 중 정확도가 가장 낮은 키
3. **속도가 목표 미달인 키** 중 속도가 가장 느린 키
4. 모든 키가 목표를 넘었으면 정확도가 가장 낮은 키 (같으면 느린 키)

목표를 이미 넘은 키는 다른 키가 목표 미달인 동안에는 집중 키가 되지 않습니다.

## 연습 문장

- **영어 단어: 내장 SCOWL 10단계 (가장 흔한 단어 약 4천 개)**
  - SCOWL(맞춤법 검사기용 영어 단어 목록)에서 가장 흔한 단계만 씀. 활용형 포함 (`drive`, `drives`, `driving`)
  - 영어 소문자 2글자 이상만, 그 밖에 거르는 단어 없음
  - 예: 키 4개(`e t s h`, 13단어) `the she these sheet test teeth`, 키 5개(+`a`, 30단어) `hate state eat that heat`
  - 키 4개 단계는 단어가 13개뿐이라 같은 단어가 자주 반복됨. 키가 하나 더 열리면 30개로 늘어남
- **진짜 단어 우선**: 집중 키가 든 진짜 단어가 15개 이상이면 진짜 단어만 씀
  - 그보다 적으면 진짜 단어를 한 줄에 각 2번까지 먼저 쓰고, 남는 자리만 가짜 단어로 채움
  - 가짜 단어는 영어 글자 연결 빈도로 만듦 (예: `flads`, `kalds`). 집중 키가 든 진짜 단어가 아예 없을 때 주로 나옴
- **틀린 단어 복습**: 한 줄을 끝낼 때 틀린 키가 있었던 단어를 기억해 두었다가 다음 줄들에 다시 넣음
  - 단어 목록에 있는 진짜 단어만 기억함 (가짜 단어는 안 넣음)
  - **지금 집중 키가 들어간 단어일 때만** 다시 나옴. 집중 키가 바뀌면 그 키가 든 틀린 단어만 나옴
  - 다시 나왔을 때 한 번에 맞게 치면 목록에서 빠짐. 최대 100개까지, 진도 파일에 같이 저장
- **약한 연결 우선**: 틀린 키를 누르면 **바로 앞 키 → 그 키** 연결을 기억함 (`the`에서 h를 틀리면 `th`,
  단어 첫 글자를 틀리면 단어 시작 → 그 글자)
  - 줄을 만들 때 그 연결이 든 진짜 단어를 더 자주 고름 (점수 1점당 가중치 +2배). 집중 키 조건은 그대로
  - 같은 연결에서 또 틀리면 점수가 오르고(최대 5), 한 번에 맞게 칠 때마다 0.8배로 줄어 0.3 밑이면 목록에서 빠짐
  - 최대 50개, 진도 파일에 같이 저장. 한글은 두벌식 키 기준 (예: `ㄱ → ㅏ`)
- **모든 단어에 집중 키가 들어감** (진짜 단어는 집중 키가 든 것만 고르고, 가짜 단어에도 항상 넣음)

## 단어 목록 출처

영어 단어는 [SCOWL](http://wordlist.aspell.net/) (Spell Checker Oriented Word Lists, Kevin Atkinson)
2020.12.07 판의 10단계에서 가져왔습니다. 저작권 표시와 사용 조건은 `assets/words/scowl/COPYRIGHT.txt`에 있습니다.
`scripts/import_scowl.py`로 다시 만들 수 있습니다. 단계를 늘리려면 스크립트의 `LEVELS`와 `src/words/mod.rs`의 `SCOWL`에 더하면 됩니다.

## 한글 (`--lang ko`)

- **OS 입력기는 영문으로 두고** 칩니다. 한글 조합은 프로그램이 합니다.
  한글 입력기가 켜져 있으면 화면에 안내가 나옵니다.
- **자판은 영어 레이아웃의 글자를 따라갑니다.** 표준 두벌식 대응(`q`=ㅂ, `w`=ㅈ, `e`=ㄷ, `r`=ㄱ …)을 그대로 쓰므로,
  레이아웃이 바뀌어도 `q`가 있는 자리가 ㅂ입니다.
- **Shift 글자**: `Q`=ㅃ `W`=ㅉ `E`=ㄸ `R`=ㄲ `T`=ㅆ `O`=ㅒ `P`=ㅖ. 언락 순서에 따로 들어가고, 다른 키처럼 빈도로 순서가 정해집니다.
- 단어는 키 순서로 바꿔서 비교합니다 (`학교` → `gkrry`). 목표 줄 아래에 친 키가 조합된 모습(`ㅎ` → `하` → `학`)이 보입니다.
- 진짜 단어가 모자랄 때만 열린 자모로 만든 음절(홑모음만, 받침은 ㄱ ㄴ ㄹ ㅁ ㅂ ㅅ ㅆ ㅇ만)로 채웁니다.
- 속도는 분당 타수(KPM, keystrokes per minute)로 표시합니다. 진도는 영어와 따로 저장됩니다 (`<레이아웃>-ko.json`).
- 계산 결과 (학습용 어휘 빈도 기준):
  - `layouts/mine.txt`: `ㅏ ㅇ ㄷ ㅎ`(k d e g) → `ㅣ ㅗ ㄱ ㄹ ㄴ ㅅ ㅓ ㅈ ㅜ ㅁ ㅂ ㅡ …`
  - QWERTY: `ㅏ ㄷ ㄴ ㅎ`(k e s g) → `ㅇ ㅣ ㅗ ㄱ ㄹ ㅅ ㅓ ㅈ ㅜ ㅁ ㅂ ㅡ …`
  - 단어가 사전 기본형이라 `-다`, `-하다`에 쓰는 `ㅏ ㄷ ㅎ`이 시작 키에 들어감. Shift 키는 `ㄲ`이 가장 먼저

### 한글 단어 목록

국립국어원 「한국어 학습용 어휘 목록」(2003)의 A·B·C등급 **5,476개**를 씁니다 (`assets/words/ko/learner/`).
완성된 한글로 저장하고, 실행할 때 두벌식 키로 바꿉니다.

| 파일 | 등급 | 단어 수 | 가중치 | 예시 |
|---|---|---|---|---|

| `b.txt` | B | 1,965 | 1.5 | `청소기 상자 우울하다 통장` |

- 동음이의어 번호(`가다01` → `가다`)를 떼고, 여러 등급에 나오는 단어는 더 쉬운 등급에만 넣었습니다.
